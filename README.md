### Cristhian Storm / Full Stack Developer

Desarrollador de software y estudiante de Ingeniería Informática en Paraguay. Construyo aplicaciones web, servicios backend y soluciones con bases de datos relacionales. Me interesan la automatización, la mejora de sistemas, el diseño UI/UX y los videojuegos.

### Tecnologías

Frontend: HTML, CSS y JavaScript. Backend: Java, Spring Boot, Spring Security, Python, Flask y PHP. Datos: Oracle, MySQL, H2, SQL y JPA. Herramientas: Git, GitHub, Maven y Docker. Unity y C# se presentan como interés declarado, sin atribuirles un proyecto público disponible.

### Sistemas construidos

- [Tutorías online](https://github.com/CristhianStorm/Curso-sincronico): aplicación académica en Java 17/Spring Boot, Spring Security, JPA y Oracle. Registro, JWT, roles, consultas, foros, adjuntos, informes PDF e integración Jitsi/JaaS. Se identificaron en el código; no implican una demo productiva ni una auditoría de seguridad.
- [API de productos](https://github.com/CristhianStorm/java/tree/main/CrusoJava/curso_java-main/productoapi): práctica de Java 21/Spring Boot, JPA y H2 en memoria. CRUD, validaciones de precio y stock y estadísticas. El controlador accede directamente al repositorio; el servicio existente todavía no integra ese flujo.
- [Laboratorio Python](https://github.com/CristhianStorm/Python): ejercicios, servicios Flask, blueprint de login, Swagger UI, consultas MySQL y Docker Compose. Requieren adaptar configuración local y dependencias históricas.
- [Interfaces web](https://github.com/CristhianStorm/CristhianStorm.github.io): Neo Jumper y una práctica visual de acceso con HTML/CSS/JavaScript. No se atribuye autenticación backend a los formularios.
- [PHP](https://github.com/CristhianStorm/PHP): ejercicios de arreglos, clases y herencia; no una aplicación completa.

### Arquitectura y evidencia

El diagrama Frontend → API → Lógica → Datos es conceptual. En [tutorías](https://github.com/CristhianStorm/Curso-sincronico/tree/main/src/main/java/com/gestion/emprendedora) existen controladores, servicios, repositorios JPA y entidades; algunos controladores acceden directamente a datos. El diagrama no atribuye una arquitectura uniforme ni distribuida.

Evidencias: [Maven de tutorías](https://github.com/CristhianStorm/Curso-sincronico/blob/main/pom.xml), [API de productos](https://github.com/CristhianStorm/java/tree/main/CrusoJava/curso_java-main/productoapi/src/main/java/com/cristhianstorm/productoapi), [Flask/MySQL/Docker](https://github.com/CristhianStorm/Python/tree/main/Python/clase5), [ejercicios PHP](https://github.com/CristhianStorm/PHP). Los gráficos son originales y conceptuales; no son capturas de interfaces.
